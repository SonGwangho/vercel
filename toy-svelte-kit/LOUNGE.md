# 모닥불 라운지

## 화면과 조작

- `/lounge`: 닉네임과 외형을 정하고 캠핑장을 선택한다. 닉네임은 정규화 후 1~6자이며 같은 캠핑장 안에서 중복할 수 없다. 이름표는 전체 이름을 표시한다.
- `/lounge/1`~`/lounge/3`: 모닥불이 켜진 숲속 캠핑장. 텐트, 등불, 통나무 의자, 피크닉 테이블을 배치했다. 카메라는 내 캐릭터를 따라가며 휠과 +/− 버튼으로 확대할 수 있다. 상단 텐트 버튼은 모닥불 앞으로 이동한다.
- 좌클릭 또는 터치로 이동한다. 모닥불·텐트·테이블은 경로를 돌아간다. 경로 계산은 서버와 클라이언트가 공유한다.
- 캐릭터와 바닥 음식을 우클릭하면 행동 메뉴가 열린다. 터치는 450ms 길게 누른다. 이름표에서 Enter 또는 ContextMenu 키를 눌러도 된다.
- 음식 줍기는 가방에 넣는 동작이다. 내 캐릭터 메뉴에서 **손에 들기**를 선택하고, 이후 별도로 **먹기**를 선택한다. 손에 든 음식은 3D 캐릭터에 표시되며 게임 화면의 작은 음식 버튼에서도 먹거나 다시 가방에 넣을 수 있다.
- 가방 전체·참여자 목록·채팅 기록을 별도 화면으로 펼치지 않는다. 내 캐릭터 버튼은 우클릭과 같은 메뉴를 연다.
- Enter 또는 한마디 버튼으로 최대 60자의 대화를 보낸다. 말풍선은 내용에 맞춰 너비와 높이가 늘어나며 내부 스크롤과 말줄임을 사용하지 않는다. 최근 대화는 화면 읽기 프로그램에도 알린다.
- 먼 대상의 줍기나 상호작용을 선택하면 가까이 이동한 뒤 실행한다. 새 이동·Escape·대상 이탈은 예약을 취소한다.
- 악수·포옹·음식 선물은 상대 수락이 필요하다. 동의 대기 중에는 양쪽에 추가 요청을 보낼 수 없다. 12초 후 요청이 만료된다.
- 펀치는 상대 동의 없이 실행하며 1.5초 기절한다. 기절 중 이동·채팅·음식 사용·상호작용은 차단된다. 이미 행동하거나 요청을 기다리는 대상에게 중첩 실행할 수 없다.
- 먹기는 손을 입으로 올리는 동작, 줄어드는 음식, 부스러기와 효과음을 사용한다. 움직임 줄이기 설정에서는 장식 입자와 모닥불의 흔들림을 줄인다.

## 기본값과 외형

`src/lib/assets/data/lounge/config.json`과 `campground.json`에서 관리한다.

- 캠핑장 3개, 각각 최대 16명.
- 논리 공간 2400×1800, 이동 속도 초당 300. 이전 1000×640 공간 대비 면적은 6.75배다.
- 음식은 삼각김밥·닭다리·피자. 채널 전체에서 1분마다 무작위 접속자 근처에 하나 생성한다. 첫 입장 때 즉시 만들거나 놓친 주기를 한꺼번에 생성하지 않는다.
- 바닥 음식은 최대 2개, 유지 시간 2분. 가방 용량은 5개다. 먹기에는 별도의 능력치 효과가 없다.
- 실제 입력 없이 5분이 지나면 퇴장한다. 연결 확인용 ping/pong과 서버 heartbeat는 활동으로 인정하지 않는다. 네트워크가 끊긴 접속은 재연결을 위해 최대 45초 유지한다.
- 머리 8종, 상의 5종, 긴바지·반바지·긴치마·짧은 치마를 지원한다. 머리색 10개, 상의색 12개, 바지색·치마색 각 10개를 제공한다. 외형 목록은 `appearance.json`에서 관리한다.
- 프로필과 효과음 설정은 기존 IndexedDB `Storage`를 사용한다. 외형 값은 서버에서 허용 목록으로 정규화한다.

## 실시간 연결

브라우저의 게임 상태 수신은 HTTP long polling 대신 WebSocket을 사용한다.

1. `GET /api/lounge/ticket`은 기존 SvelteKit 훅을 거쳐 60초짜리 서명 티켓을 발급한다.
2. 브라우저가 같은 출처의 `/api/lounge-socket`으로 연결한다. 서버는 Origin과 티켓 서명을 확인한다.
3. 입장·복귀·이동·대화·음식·동의를 같은 연결로 전달한다. 서버는 바뀐 플레이어와 목록만 클라이언트에 전송한다.
4. 채널별 메모리 권한 서버에서 이동·음식 소유·동의·기절을 판정한다. 해당 인스턴스에 연결된 사용자에게는 DB 저장 완료를 기다리지 않고 바로 반영한다.
5. 여러 함수 인스턴스가 생기면 Neon의 세션 advisory lock으로 채널 권한 서버를 하나만 정한다. LISTEN/NOTIFY로 명령과 상태를 중계하고 상태 전송은 최신 값으로 합친다. 이 경우 인스턴스 간 전달에는 Neon 왕복 시간이 남는다.
6. 복구 상태는 10초 간격과 연결 인계 때 checkpoint에 기록한다. 매 이동마다 행을 읽고 갱신하는 방식은 사용하지 않는다. checkpoint 저장 완료는 일반 입력 응답을 막지 않는다.

복구용 `lounge_realtime_checkpoints` 테이블은 첫 연결에서 생성한다. 기존 `DATABASE_URL` 계정에 테이블 생성·조회·쓰기 권한이 필요하다. LISTEN과 세션 잠금을 유지하도록 Neon pooler 호스트의 `-pooler`를 제거한 direct 연결을 사용한다. 공개 메시지에는 세션 토큰 해시와 접속 관리 필드를 넣지 않는다.

새 외부 서버 계정이나 SSH 설정은 요구하지 않는다. `DATABASE_URL`은 기존 Vercel 환경 변수를 사용하며 티켓 서명에도 이용한다. 별도의 서명 키를 분리할 경우에만 `LOUNGE_SOCKET_SECRET`을 설정한다.

## 배포 구성

[Vercel WebSocket Functions](https://vercel.com/kb/guide/do-vercel-serverless-functions-support-websocket-connections)의 Node HTTP server + ws 방식을 사용한다.

- `src/lib/server/lounge/entry.ts`: WebSocket 서버 진입점.
- `scripts/lounge-adapter.mjs`: 기존 SvelteKit 어댑터가 끝난 뒤 실시간 함수를 Build Output API의 `.vercel/output/functions/lounge-realtime.func`로 패키징한다. `/api/lounge-socket` 한 경로만 해당 함수로 연결한다.
- 루트 `api/` 디렉터리로 함수를 추가하지 않는다. [SvelteKit의 기존 `/api/*` 경로가 가려지는 충돌](https://svelte.dev/docs/kit/adapter-vercel#Notes-Vercel-functions)을 피하기 위한 구성이다.
- 게임 함수의 배포 지역은 `icn1`, 실행 한도는 300초다. 일반 웹/API 함수의 지역 설정은 유지한다. `vercel.json`에서 Fluid Compute를 활성화한다.
- 240~255초마다 연결을 교체하고 기존 세션으로 자동 복귀한다. 복귀 중에는 새로운 행동을 잠시 막으며 소비성 행동을 무조건 재전송하지 않는다.
- `vite.config.ts`는 개발 서버에도 동일한 WebSocket 핸들러를 연결한다. 개발 시에도 기존 `DATABASE_URL`이 필요하다.

기존 HTTP lounge API는 이전 클라이언트 호환 코드로 남아 있다. 새 게임 클라이언트는 해당 상태 조회·명령 경로를 사용하지 않으며, 이전 DB 방 상태와 새 메모리 방 상태는 서로 섞지 않는다. 배포 버전별 실시간 범위도 분리한다.

## 렌더링과 반응

- Three.js 렌더러를 동적으로 불러온다. 캐릭터와 미리보기는 같은 모델을 공유한다.
- `src/lib/lounge/character.ts`에서 얼굴 윤곽·귀·코·헤어 8종·옷·손·운동화를 직접 구성한다. `character.json`은 체형과 기본 팔레트를 정의한다. 얼굴은 눈동자·하이라이트·눈 깜빡임·먹는 표정이 있고, 셔츠 깃·후드 끈·치마 주름·신발 끈을 별도 형태로 표현한다.
- 캐릭터는 vertex color와 4단계 toon 재질을 사용한다. 같은 부위는 참가자끼리 지오메트리를 공유하고 instancing으로 그리며 사용하지 않는 헤어·의상 부위는 감춘다. 외부 모델 파일·텍스처 다운로드나 후처리 패스는 추가하지 않는다.
- 팔은 2본 IK로 손의 목표 위치에 맞춰 팔꿈치를 접는다. 손에 든 음식도 그 위치를 따라간다. 다리는 허벅지·종아리·신발을 나누어 무릎이 접히도록 움직인다. 새 체형에 맞춰 이름표·기절 표시·미리보기 카메라 위치를 조정했다.
- 나무·풀·돌·텐트·가구는 지오메트리와 재질별 instanced mesh로 묶는다. 모닥불과 불씨는 고정 개수의 인스턴스로 움직인다. 그림자 맵·후처리·물리 엔진은 사용하지 않는다.
- 캐릭터 외형의 GPU 색상은 외형이나 배치 슬롯이 바뀔 때만 갱신한다. DPR 상한은 1.5, 장식 파티클 상한은 120개다.
- 애니메이션과 이름표 좌표는 Svelte 반응형 상태를 매 프레임 변경하지 않고 직접 갱신한다. 이름·말풍선 배치는 최대 100ms에 한 번 계산한다. 이동 중 최대 60fps, 정지 중 최대 24fps로 제한한다. 측정된 성능 수치가 아니다.
- 내 이동은 클릭 즉시 예측한다. 목적지 전송은 40ms 안에서 최신 클릭으로 합치고 이전 이동 응답을 기다리지 않는다. 음식 들기·먹기·줍기·펀치에도 즉시 피드백을 준다.
- 다른 사용자는 수신한 경로를 현재 서버 시각으로 보간한다. 별도 프레임 지연 버퍼는 두지 않는다. ping 왕복 시간을 이용해 시계를 보정한다.
- 화면이 숨겨지면 렌더링을 멈춘다. 연결은 유지하되 실제 활동이 없으면 5분 규칙대로 퇴장한다. 퇴장 시 관찰자·이벤트·오디오·GPU 리소스를 해제한다.
- Taste Skill과 Impeccable의 화면 위계·가독성·상태 표현 원칙, 프로젝트 `DESIGN.md`의 한글 폰트·블루 컨트롤·라이트/다크 토큰을 적용한다. 캠핑장 도형은 코드로 구성한다.

## 한계와 검증 범위

네트워크와 여러 인스턴스 사이의 중계 지연은 남는다. 갑작스러운 모든 인스턴스 종료에서는 마지막 checkpoint 이후의 일부 상태가 유실될 수 있고, 새 배포나 만료된 세션에서는 다시 입장해야 한다. 10초 checkpoint는 게임 기록을 영구 보존하는 기능이 아니다.

사용자 요청에 따라 빌드·타입 검사·자동 테스트·브라우저 실행·다중 사용자 검증·성능 측정·실제 DB 접속·배포 확인을 실행하지 않았다. 배포에 필요한 코드를 작성한 상태이며 실서비스에서 작동을 확인한 결과는 아니다.
