# 라운지

## 화면과 조작

- `/lounge`: 닉네임, 캐릭터 색상, 채널을 선택하는 입장 화면.
- `/lounge/1`, `/lounge/2`, `/lounge/3`: Three.js로 그리는 3D 공간. 입장 후 사이트 메뉴를 숨기고 게임이 화면 전체를 사용한다.
- 좌클릭 또는 터치로 이동한다. 목적지 표시와 걷기는 클릭 즉시 시작한다. 마우스 휠이나 화면의 +/− 버튼으로 확대·축소한다. 좁은 화면에서는 카메라가 내 캐릭터를 따라간다.
- 캐릭터와 바닥 음식을 우클릭하면 그 자리에서 행동 메뉴가 열린다. 터치에서는 450ms 길게 누른다. 이름표에 키보드 초점을 맞추고 Enter를 눌러도 열린다.
- 내 캐릭터를 우클릭하면 보유 음식을 먹는다. 화면 아래의 ‘내 캐릭터’ 버튼도 같은 메뉴를 연다. 가방·참여자 목록·대화 기록을 별도 패널로 표시하지 않는다.
- Enter 또는 ‘한마디’를 눌러 입력하고 전송하면 캐릭터 머리 위에 10초 동안 말풍선이 뜬다. 전송은 즉시 로컬 말풍선에 반영하고 서버가 거부하면 입력 내용을 복구한다. 표시 이름과 대화 내용은 HTML로 해석하지 않는다. 화면 읽기 프로그램에는 최근 대화를 별도로 알린다.
- 긴 말은 줄 수로 잘라내지 않는다. 화면 높이가 부족할 때는 말풍선 안에서 스크롤해 읽는다. 말풍선 위의 휠은 화면 확대 대신 글을 스크롤한다.
- 멀리 있는 음식의 줍기나 다른 사람의 행동을 선택하면 가까이 이동한 뒤 실행한다. 새 이동이나 Escape는 예약한 행동을 취소한다. 상대가 떠나거나 다른 행동을 시작한 경우에도 취소한다.
- 악수·포옹·음식 건네기는 상대 수락 후 실행한다. 대기 중에는 양쪽에게 다른 상호작용을 요청할 수 없다. 요청은 취소·거절할 수 있으며 12초 후 만료된다.
- 펀치는 상대 동의 없이 실행된다. 맞은 사람은 1.5초 동안 이동·채팅·음식 사용·상호작용을 할 수 없다. 행동·동의 대기·기절 중인 사람에게 중첩 실행할 수 없다.
- 먹기는 손을 입으로 올리는 동작, 음식이 작아지는 연출, 부스러기, 짧은 효과음으로 표시한다. 줍기·펀치·상호작용도 동작과 입자 효과를 사용하며, 기절에는 머리 위로 도는 별을 표시한다. 효과음은 끌 수 있고 설정은 IndexedDB에 저장한다.

## 기본값

`src/lib/assets/data/lounge/config.json`에서 변경한다.

- 채널 3개, 채널별 16명.
- 논리 공간 1000×640, 이동 속도 초당 240.
- 음식 종류: 삼각김밥, 닭다리, 피자. 비어 있던 채널의 첫 입장에는 음식을 놓지 않는다. 사람이 있는 동안 **채널 전체에서 1분마다 하나**를 임의의 접속자 근처에 생성한다. 놓친 주기를 한꺼번에 생성하지 않는다.
- 바닥 음식 유지 시간 2분, 최대 2개. 이전 버전에서 쌓인 음식도 서버 상태 정리 시 최대 2개로 줄인다.
- 음식은 5개까지 보유한다. 먹으면 소모되며 별도의 능력치나 회복 효과는 없다.
- 접속은 12초 간격으로 갱신한다. 60초간 갱신되지 않은 사용자는 나간 것으로 처리한다. 퇴장 후 보유 음식을 복구하지 않는다.
- 생성·만료 처리는 채널 API 요청 시 수행한다. 별도 백그라운드 스케줄러는 없으며 접속자의 정상 조회 간격 안에서 반영된다.

## 렌더링과 입력

- `src/lib/lounge/scene.ts`가 Three.js 장면과 입력을 관리한다. Three.js와 타입 패키지는 `^0.187.0`을 추가했다. 클라이언트에서 동적 import하므로 입장 화면과 서버 렌더링에서는 WebGL을 만들지 않는다.
- 3D 캐릭터는 부위별 instanced mesh를 공유한다. 지오메트리와 재질을 재사용하며 파티클은 120개로 제한한다. 그림자 맵·후처리·물리 엔진은 사용하지 않는다. DPR 상한은 1.5다.
- 애니메이션은 Svelte 반응형 상태를 프레임마다 다시 만들지 않는다. WebGL과 이름표 위치를 직접 갱신하고 이름·말풍선의 충돌 배치는 최대 100ms에 한 번 계산한다. 움직일 때 최대 60fps, 정지 중 최대 24fps로 제한한다. 이는 프레임 제한 설정이며 측정된 성능 수치가 아니다.
- 이동 전송은 최근 목적지로 합치며, 이동 요청이 진행 중이어도 다음 클릭을 즉시 화면에 반영한다. 먹기·줍기·펀치는 즉시 로컬 피드백을 표시하고 서버 결과로 확정하거나 취소한다. 이동 속도와 거리·보유 음식·동의 상태의 최종 판단은 서버에 있다.
- 화면이 숨겨지면 조회와 애니메이션을 중단한다. 퇴장 시 루프, 관찰자, 이벤트, 오디오, WebGL 리소스를 정리한다. WebGL 초기화 실패나 컨텍스트 손실은 게임 안에서 안내한다.

## 서버와 데이터

기존 `DATABASE_URL`과 `@neondatabase/serverless`를 사용한다. 서버 통신은 SvelteKit 라우트에서 처리한다.

- `GET /api/lounge/channels`: 채널과 현재 인원.
- `POST /api/lounge/join`: 입장과 개별 세션 발급.
- `GET /api/lounge/[channel]?since=[revision]&wait=1`: 인증된 상태 조회와 접속 갱신. 변경을 기다리는 long polling이며, 6초간 변경이 없으면 버전과 서버 시각만 반환한다.
- `POST /api/lounge/[channel]`: 이동·대화·동의·상호작용·음식·퇴장 명령.

첫 API 호출에서 `lounge_rooms` 테이블과 채널 행을 생성한다. 해당 테이블의 생성·읽기·쓰기 권한이 필요하다. 이 변경 작업에서 DB에 직접 접속하거나 스키마 생성 명령을 실행하지 않았다.

상태는 Neon JSONB 행에 저장한다. 이동은 현재 위치의 보간과 토큰·접속·기절·행동 제한을 단일 SQL `UPDATE` 안에서 평가한다. 자신의 이동만 변경하므로 다른 사람의 이동 때문에 전체 채널을 다시 읽고 재시도하지 않는다. 이동 명령은 재전송할 때 같은 목적지를 새 경로로 처리하며 소비성 행동의 중복 방지 목록에는 넣지 않는다.

그 밖의 행동은 `revision` 조건으로 갱신한다. 최근 캐시로 먼저 시도해 선행 조회를 생략하고, 경합하거나 캐시의 전제 조건에서 실패하면 최신 행을 다시 읽는다. 음식 중복 획득, 동일 상대의 중복 예약, 다른 사용자의 음식 사용은 서버에서 막는다. 캐시는 인스턴스 간 정합성의 근거로 사용하지 않는다.

조회는 85ms 캐시와 진행 중인 읽기 작업을 공유한다. 전체 대화 기록 대신 최대 24개의 최근 말풍선과 4개의 안내만 보관하며, 대화는 20초 후 정리해 전송량과 JSONB 갱신 크기를 줄인다.

닉네임은 계정 인증을 대신하지 않는다. 입장마다 생성한 임의 토큰을 헤더로 전달하고 서버에는 해시만 저장한다. 공개 응답에는 해시를 포함하지 않는다. 프로필과 재입장 세션은 기존 IndexedDB `Storage`를 사용한다.

## 동기화의 한계와 검증 범위

현재 전송은 **HTTP long polling**이다. 같은 서버 인스턴스에서 상태가 확정되면 기다리던 요청을 즉시 깨운다. 다른 인스턴스의 변경은 같은 채널의 진행 중인 읽기를 공유하면서, 2명 이상일 때 100ms·혼자일 때 350ms 목표 간격으로 DB에서 확인한다. DB 응답 시간에 따라 실제 확인 간격은 늘어난다. 응답 뒤에는 클라이언트의 추가 350ms 대기 없이 바로 다음 수신을 시작한다.

한 번에 하나의 수신 요청만 유지하며 6초마다 갱신한다. 실패하면 재연결 간격을 늘리고 이전 버전 응답은 버린다. 응답에 서버 처리·대기 시간을 포함하여 긴 수신 대기를 네트워크 지연이나 시계 오차로 잘못 계산하지 않는다. 서버 시각은 왕복 지연이 짧은 표본으로 완만하게 보정한다. 이동은 첫 클릭 즉시 반영하고, 연속 클릭 전송 간격은 40ms·진행 중 요청 뒤의 추가 대기는 0ms로 설정한다.

내 입력 반응과 렌더링은 서버 응답 대기에서 분리했다. 다른 사람의 이동은 별도의 프레임 버퍼로 지연시키지 않고 서버 경로를 현재 시각으로 보간한다. 새 경로를 받을 때의 위치 차이만 짧게 줄여 순간이동처럼 보이는 현상을 완화한다. 다른 사람의 행동을 받는 시간에는 네트워크·DB 지연이 남는다. WebSocket 서버를 추가 배포하거나 외부 실시간 서버를 수정한 변경은 아니다.

Taste Skill과 Impeccable의 앱 화면·Optimize·Operate 지침을 적용했다. `DESIGN.md`의 블루 포인트, 한글 폰트, 차콜 다크 모드, 표면·컨트롤 토큰을 사용한다. 캐릭터·음식·방은 코드로 만든 3D 도형이다.

사용자 요청에 따라 빌드, 타입 검사, 자동 테스트, 브라우저·다중 사용자 실행 검증, 성능 측정은 실행하지 않았다.
