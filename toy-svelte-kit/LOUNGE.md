# 라운지

## 화면과 조작

- `/lounge`: 닉네임, 캐릭터 색상, 채널을 선택하는 입장 화면.
- `/lounge/1`, `/lounge/2`, `/lounge/3`: 각 채널의 공간. 같은 채널의 접속자가 이동·대화·음식·상호작용 상태를 공유한다.
- 좌클릭으로 이동한다. 작은 지도에서도 목적지를 선택할 수 있다.
- 캐릭터와 바닥의 음식을 우클릭하면 행동 메뉴가 열린다. 터치에서는 길게 누르며, 키보드에서는 대상에 초점을 맞추고 Enter를 누른다.
- 내 캐릭터를 우클릭하면 보유한 음식을 먹을 수 있다. 다른 사람을 우클릭하면 악수, 포옹, 음식 건네기, 펀치를 선택한다.
- 악수·포옹·음식 건네기는 상대 수락 후 실행한다. 대기 중에는 양쪽 사용자에게 다른 상호작용을 예약할 수 없다. 요청은 취소·거절할 수 있으며 12초 후 만료된다.
- 펀치는 상대 동의 없이 실행된다. 맞은 사람은 1.5초 동안 이동·채팅·음식 사용·상호작용을 할 수 없다. 이미 상호작용·동의 대기·기절 중인 사람을 대상으로 중첩 실행할 수 없다.
- 닉네임은 캐릭터 머리 위에 표시된다. 채팅은 7초 동안 말풍선으로 표시하고, 같은 채널의 최근 80개 대화를 별도 기록에 둔다. 긴 말풍선은 3줄까지 표시한다. 말풍선이 모두 들어갈 자리가 없으면 최신 대화를 우선 표시하며 전체 내용은 기록에서 읽을 수 있다.
- 소규모 공간에서도 이름을 읽을 수 있도록 이름표와 말풍선을 캐릭터와 별도로 배치한다. 화면이 좁으면 카메라가 내 캐릭터를 따라가고, 대화·참여자·보유 음식 패널은 탭으로 전환한다.

## 최초 기본값

`src/lib/assets/data/lounge/config.json`에서 변경한다.

- 채널 3개, 채널별 16명.
- 음식 종류: 삼각김밥, 닭다리, 피자. 채널의 첫 입장 때 5개를 놓고, 사람이 있는 동안 10초 간격으로 추가한다. 바닥에는 최대 12개, 바닥 음식의 유지 시간은 2분이다.
- 음식은 5개까지 보유한다. 먹으면 소모되며 별도의 능력치나 회복 효과는 없다.
- 일정 거리에 접근해야 상호작용하거나 음식을 주울 수 있다. 메뉴에서 가까이 이동할 수도 있다.
- 접속은 12초 간격으로 갱신한다. 60초간 갱신되지 않은 사용자는 나간 것으로 처리한다. 음식과 캐릭터는 현재 입장에 속하며 퇴장 후 보유 음식을 복구하지 않는다.

## 서버와 데이터

기존 `DATABASE_URL`과 `@neondatabase/serverless`를 사용한다. 새 패키지나 별도 WebSocket 서버 설정은 추가하지 않았다. 서버 통신은 다음 SvelteKit 라우트를 사용한다.

- `GET /api/lounge/channels`: 채널과 현재 인원.
- `POST /api/lounge/join`: 닉네임·색상·채널로 입장하고 개별 세션을 발급.
- `GET /api/lounge/[channel]`: 인증된 세션의 채널 상태 확인과 주기적 접속 갱신.
- `POST /api/lounge/[channel]`: 이동·대화·동의·상호작용·음식·퇴장 명령.

첫 라운지 API 호출에서 `lounge_rooms` 테이블과 채널 행을 자동 생성한다. 따라서 `DATABASE_URL`의 역할에는 해당 테이블을 생성하고 읽고 쓸 권한이 필요하다. 이 작업에서는 데이터베이스에 직접 접속하거나 스키마 생성 명령을 실행하지 않았다.

채널 상태는 Neon의 JSONB 행에 저장하며, `revision` 조건이 일치할 때만 갱신한다. 경합하면 최신 상태를 다시 읽어 처리한다. 음식의 중복 획득, 동일 상대에게 동시 요청, 다른 사용자의 소유 음식 사용은 클라이언트 표시와 별개로 서버에서 판정한다. 이동 속도·거리, 요청 수락 권한, 기절·행동 제한도 서버가 확인한다.

닉네임은 표시 이름이며 계정 인증을 대신하지 않는다. 입장마다 생성한 임의 토큰을 요청 헤더로 전달하고 서버에는 토큰 해시만 저장한다. 공개 채널 응답에는 토큰 해시를 포함하지 않는다. 프로필과 재입장 세션은 기존 IndexedDB `Storage`를 사용하며, 브라우저 저장이 불가능해도 현재 화면에서는 입장을 유지한다.

## 동기화와 제한

- 현재 통신 방식은 700ms 간격의 HTTP 상태 조회다. WebSocket 푸시 방식이 아니므로 다른 사람의 행동 표시는 네트워크 왕복 시간과 조회 간격만큼 늦을 수 있다.
- 클릭한 목적지만 전송하고 캐릭터 이동은 시작·도착 시각으로 보간한다. 내 이동은 먼저 표시하고 서버가 거부하면 서버 위치로 돌아간다.
- 요청 중 상태 조회가 겹치지 않도록 하고, 이전 버전 응답은 적용하지 않는다. 실패 시 재연결 간격을 늘린다.
- 화면을 숨기면 조회와 애니메이션을 중단한다. 움직임이 없는 동안은 표시 갱신 빈도를 낮춘다.
- 사용자가 적은 소규모 라운지를 위한 초기 구현이다. 접속 인원이 늘면 상태 조회 API와 데이터베이스 부하를 측정하고 WebSocket 기반 외부 실시간 서버 등으로 전송 계층을 확장할 수 있다.

Neon 드라이버 연결 방식은 [공식 문서](https://neon.com/docs/serverless/serverless-driver)를 참고했다.

## 디자인 및 검증 범위

Taste Skill의 앱 화면 지침과 Impeccable의 Operate·craft floor를 적용했다. 기존 `DESIGN.md`의 블루 포인트, 한글 폰트, 차콜 다크 모드, 공통 컨트롤과 표면 토큰을 유지한다. 라운지의 캐릭터·음식·공간은 외부 이미지 대신 단순한 SVG와 CSS 도형으로 구성했다.

사용자 요청에 따라 빌드, 자동 검사, 브라우저·다중 사용자 실행 검증, 성능 측정은 실행하지 않았다.
